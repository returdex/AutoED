# Quick Task 260904-w8b：发布 macOS 测试操作与证据指南

## Objective

在项目根目录 `share/` 创建一份不含敏感信息、可供其他用户直接查看的中文 macOS 测试指南。指南必须忠实反映当前停止状态和 `AGENTS.md`、Phase 1 macOS UAT、Phase 2 Plan 02-14 的硬门槛；它只提供操作说明与证据格式，不执行安装、更新、登录、OS 授权、重启或学校访问。

## Task 1：创建中文 macOS 测试指南

**Files:** `share/macos-testing-guide.md`

**Action:**

创建 `share/`（如不存在）并写入中文指南，按以下顺序组织，内容必须是可执行步骤而不是泛泛说明：

1. **当前状态与开始前硬门槛**：明确 beta.31–beta.39 是不可覆盖、不可重试、不可删除或改名的失效历史；当前没有可供更新的候选，因此读者不得运行历史 prompt、使用 `latest`、自行修改 version/tag/URL/hash，或把发布/下载/匿名验签结果当作本机已更新。只有控制器明确提供新的 exact version/tag、macOS artifact bytes/SHA-256、manifest/signature/build identity、匿名可获取证明和逐字 verified prompt 后，才能进入更新步骤。
2. **Phase 1 macOS 原生人工清单**：提供编号步骤和每步的 expected result/evidence，包括：声明 macOS/架构与测试账户；干净账户/无宿主 Node 条件（若检测到宿主 Node，记 `not_observed`，不能宣称通过）；首次安装和数据保留；A→B 更新的 exact version/artifact/build、迁移/中断/恢复、旧受管程序与 entrypoint/process 清理；重复安装和受管进程所有权；API/Worker 健康与 Codex 完全退出后仍能用独立 CLI/echo 运行；本地管理 UI 配对、键盘 Tab/Shift+Tab/Enter、窄宽度和 200% 缩放、刷新不创建新任务；打包 synthetic diagnostics；OS 授权允许/拒绝与锁定/文件占用/恢复场景。每项区分 `pass`、`failed`、`not_observed`、`human_needed`，说明 fixture/synthetic 只能是 S/I 证据，不能填 live L。
3. **Phase 2 macOS 更新前检查**：说明用户先等待控制器确认新的候选已完成相应 release/rehearsal/匿名 availability；逐字段核对屏幕中 exact version、tag、macOS URL、bytes、SHA-256、manifest、signature、build。任一不一致、候选失效、availability 缺失、`cleanup_pending` 或 `not_observed` 都立即停止。
4. **实际更新操作**：明确必须在同一 macOS 主机和同一用户账户中新建 **local projectless Codex task**，不能选择 AutoED project、repository/worktree 或 cloud task；将控制器展示的 `release/phase2-install-prompt.md` 完整逐字粘贴，不能改写或拼接值。用户本人仅处理必要 OS 授权和 Codex 重启；updater 只更新新产品受管目录，不写 repository/`.planning`，不创建 gate receipt，不打开 Moodle/EdStem，不登录、不输入密码/MFA。若出现 `UPDATE_TASK_CONTEXT_INVALID`，解释为 task 上下文错误，不是产品更新失败；停止并按模板报告，改建正确的 projectless task 后只能重试同一 exact prompt。
5. **更新后只读核验**：列出 exact actual version/artifact/build、全部受管 entrypoints、API/Worker、paired UI、`cleanup=complete`、数据仍在、旧受管程序清理完成；来源配置保持 `moodle:not_confirmed,edstem:not_confirmed`，`school_access=not_started`，Windows 固定 `not_run/human_needed`，Phase 3 固定 `blocked`。任一 mismatch/unhealthy/unavailable/未观察到/失败都不继续来源配置或后续阶段。
6. **Phase 2 后续 live 前置（仅控制器解除更新门后）**：说明实际 macOS build 通过后仍不等于 AUTH-02 或 Phase 2 整体通过；后续真实来源测试必须由用户在官方页面手动登录/MFA，逐项验证 Profile 重开、服务/系统重启、Codex 退出、跨日复查、reauth 和实际账号绑定。指南不得要求第二账号、故意触发学校错误、API 猜测、隐藏内容或任何 source write；Windows 原生证据不能由 macOS/WSL 替代。
7. **唯一返回格式与证据规则**：提供与 02-14 schema 一致的完整 `02-14_UPDATE_RESULT` 模板，允许值限于 `pass|failed|human_needed`、规定的 `result_code`、`cleanup`、`actual_build`、`entrypoints`、`api`、`worker`、`paired_ui`，以及固定的 source configuration/school/windows/phase3 字段。明确 pass 必须同时满足 exact version/hash、`UPDATE_COMPLETE`、`cleanup=complete`、build/entrypoints matched、API/Worker healthy、paired UI ready；未知项写 `not_observed`，不能猜测。提供 Phase 1/Phase 2 证据表列，建议只填日期/时区、平台架构、公开 version/hash/build、safe code 和状态。
8. **隐私禁止项与停止条件**：明确不得回传密码、MFA、Cookie、Profile 路径或内容、token、headers、私有本机路径、姓名/邮箱、学校 URL path、课程/作业内容、原始日志、HAR/trace/录像/登录截图；禁止把这些内容放入聊天、share 文件、Git、receipt 或导出。意外请求、学校访问、legacy 访问、删除课程资料、Profile 备份/导出、越权或不确定时立即停止并只返回 safe code。

指南应以醒目的“当前不可更新”说明开头，并在更新章节重复“projectless、same host/account、exact prompt、用户本人 OS/重启、不得登录”的要求。不得写入 beta.39 的下载链接、旧候选 hash、任何实际账户或私有路径，也不得声称 Phase 1/Phase 2/Phase 3 已整体通过。仅记录已经在 `01-macos-UAT.md` 中有依据的历史 macOS 结果，并把仍开放项目标为 `not_observed`/`human_needed`。
