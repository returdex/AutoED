## 来源推进顺序

| Question | Options considered | User choice |
|---|---|---|
| 两来源如何分批 | Moodle→EdStem 分批；两者完成后统一测试；完全并行 | 两者实现完成后统一 beta 测试，因为实际使用同一登录平台认证 |
| Profile 边界 | 单一 Profile 共享 SSO、每来源独立 Profile、异常时自动拆分 | 共享优先；先测试可行性，不一致时再决定拆分 |
| 共享可行判据 | 完整门禁；首次登录；首次登录+三次重开 | 完整门禁全部一致 |
| 第二来源启动方式 | 独立入口；一个双来源按钮；登录一处后自动探测另一处 | 登录 Moodle 后自动检查 EdStem；仅在两来源已预先批准时执行有界只读探针 |

**Notes:** 用户强调 Phase 2 的核心验证之一是确认 Moodle 统一认证能否直接使 EdStem 会话有效；共享 Profile 必须以真实完整门禁验证，不能按理论直接采用。

## 登录与账户绑定展示

| Question | Options considered | User choice |
|---|---|---|
| 本地身份展示 | 本地可核对/其他出口脱敏；本地完整学校身份；全部匿名 | 本地管理页显示完整学校邮箱和显示名；其他出口仍脱敏 |
| 身份不一致 | 立即停止；以 Moodle 为准；自动退出 EdStem 重试 | 立即停止并人工核对 |
| 状态呈现 | 两个独立状态卡；统一状态；摘要+详情 | 两个独立来源状态卡和总体门禁 |
| 自动绑定 | 显式双来源确认；相同字段自动绑定；来源非对称确认；每次确认 | 先测试严格稳定身份规则；成立则自动候选绑定并首次核对，不成立则人工确认一次 |

**Notes:** 用户最初提出证据不足时退回“相同邮箱直接绑定”；讨论指出这会违反真实账户绑定核验并造成串号风险，用户选择严格规则失败时人工确认一次。GitHub 多账号/仓库身份配置移入 backlog 999.1。

## Profile 恢复与重新认证

| Question | Options considered | User choice |
|---|---|---|
| 正常启动恢复 | 后台有界探针；每次打开 Moodle；完全手动 | 后台探针，有需要才打开官方窗口 |
| 异常退出恢复 | 证明所有权和实际退出；租约到期强制重开；全部人工 | 先证明进程归属与退出，不误杀或删锁 |
| 显式退出与自然过期 | 区分用户意图；都自动打开；都只报错 | 显式退出不自动重登，自然过期提示 reauth |
| 单来源失效 | 分来源暂停并联动复查；暂停两边；默认同时恢复 | 分来源暂停；自然/暂时失败最多恢复三次，失败后使用现有提示渠道 |

**Notes:** 当前版本没有主动提示渠道时不新增通知系统，但失败必须保留在管理页和状态接口；“不管”仅指不新增渠道，不能静默忽略错误。
