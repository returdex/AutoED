## D1. 部署地点与在线要求

用户决定：**首版只在用户自己的操作系统上运行，不考虑远程；兼容 macOS 和 Windows；Ubuntu 等 Linux 不做强制兼容。**

实施解释：当前仍按每安装单用户设计，不做多用户服务。电脑/用户后台在线时同步，休眠/关机期间不执行，恢复后有限补跑。这是本机运行的可用性边界，不承诺关机后远程继续运行。

待 Phase 1 锁定：最低 Windows/macOS 版本、CPU 支持范围和 Windows 实测环境。Linux 不得阻塞首版，但不能用 Linux CI 替代 Windows 验收。

## D2. 本地持久登录会话

推荐：允许 AutoED 创建独立、仅本机使用的 Playwright Profile，用户自己登录；不复制日常浏览器/Codex Profile，不导出 Cookie，不备份或云同步 Profile。

必须理解：Profile 含有效会话凭据。它不是“只存状态描述”，也不能保证登录永不过期。操作系统文件权限/全盘加密提供一部分保护，不能保证抵御同用户恶意进程。

用户决定：**接受本地专属 Profile 持久保存学校登录会话。**

这不授权向模型输出会话秘密、不迁移宿主 Profile、不保存密码/MFA、不托管云端。OS 凭据/文件保护与实际设备加密状态在实现/安装时验证。本轮只更新设计，真实登录仍由用户在官方页面完成。

## D3. 课程材料保留与模型外发

用户决定：**希望课程完整生命周期的全部内容都能保存，覆盖作业截止日期、评分、课程资料等所有可获取信息，并让全部资料能被 Codex 或其他模型读取。**

| 范围 | 已确定目标 | 边界 |
|---|---|---|
| 本地元数据 | 课程/学期/周次/资源/消息/作业/个人状态 | 选定课程与当前用户账号范围 |
| 本地正文/文件 | 课程资料、公告、讨论、brief/rubric、本人可见成绩/反馈与附件 | 只采集有权访问和保留的内容；不包含凭据/隐藏信息 |
| Codex/模型读取 | 完整文本、原文件、结构化 metadata、定位、版本与分页 | 已知禁止外发或权限未知的材料明确标为例外；不把产品目标误当学校授权 |

首版覆盖分类详见 DESIGN 3.4：PDF、Office、文本/代码等支持正文提取；图片/扫描件/媒体/加密文件有可见的归档/提取状态。已保存原文件不等于模型已读懂；不支持类型不能静默遗漏。

注意：通过 MCP 返回正文给 Codex，也是外发。用户拥有课程访问权不必然拥有向外部模型上传材料的权利；用户的选择须与学校/材料权限相容。

不再重复询问“是否希望正文被模型读取”。实际集成时配置允许的客户端/目的地、课程范围与材料例外；权限明确的资料按用户意愿正常提供，不默认全部锁为 local_only。

设计默认调整：课程资料与版本长期保留，用户主动清理或材料政策要求时删除，不再学期结束 90 天后自动清空。磁盘预算与大媒体处理在 Phase 1 确认；磁盘满只能暂停并列出 pending，不能删历史。

用户意愿：**已确认**。具体源站授权/材料使用限制与真正可获取范围：**逐来源验证，不冒充全量可用**。

## D4. 首个可用版本的范围

用户决定：**AutoED 新项目只负责资料/消息获取、同步、归档与信息提供，不执行作业评估和辅助操作。相关功能由其他项目完成。**

因此 EvidenceLens、AssignmentFlow、ConstraintPack 编译、学生计划/进度/草稿审计从 AutoED 路线图移出，作为独立消费者。基础同步不要求 LLM Key。

一门课程/一个作业仅是早期 POC，最终要覆盖用户选定课程的完整资料分类、学期变化与历史归档，不能将 POC 当首版全部范围。

## D5. 本地安装复杂度

新建议：SQLite + 本地文件 + 最小持久 Job 状态机，避免终端用户管理 PostgreSQL/Docker。只在本机磁盘使用；事务、租约、崩溃恢复、WAL 一致性备份必须验证。

需要回答：是否希望首版终端用户无需手动安装 Node、Docker 或数据库，只安装 AutoED 即可使用？

影响：这决定依赖打包和安装门禁。若接受独立数据库且偏好成熟队列，可保留旧 PG + pg-boss 建议；不同时支持两套。

用户决定：**待确认**。

不要在这里填写密码、MFA、Cookie、API Token 或带秘密的 URL。真实身份只在本地受保护界面确认。

如果不能开展真实登录测试，Phase 2 标为 human_needed；只能声明合成测试通过。

## D7. 通知与云服务

M1 只有本地状态和资料变化消息；不做 Browserbase、Bark、Server酱或邮件发送。模型通过 API/MCP 读取归档是已确认目标，但 AutoED 自己不发起云端生成任务。

需要后续再明确：渠道、接收人、允许发送字段、quiet hours、费用、服务托管和删除策略。

状态：**当前不纳入；以后新增需明确需求，不阻止本地 M1 建项**。

推荐：独立新源码仓库；旧 AutoED 选择性复用纯逻辑与测试；Muster 作为参考，不直接复制代码；旧数据默认重新采集，导入必须 dry-run。

新工作区不等于新产品版本，不能自动创建不相干的 v0.x Release 或改动旧 Git 标签。

- D1–D4 已确认；尚未回答的其他问题不代表批准。资料读取同意不扩展为凭据泄漏、第三方云浏览器托管或源站写操作。
